# OPC 6个维度理解

根据代码 `opcV2AssessmentService.ts` 和数据库结构分析

## 六个维度及其含义

### 1. **信息处理 (info_processing)** 
- **倾向**: analytical (拆解型) ↔ integrative (整合型)
- **0-40分**: 拆解型思维 - 喜欢把大问题切成小块逐一解决，适合细分执行和具体实现
- **60-100分**: 整合型思维 - 喜欢先看全貌，找到各部分联系，适合系统架构和整体规划
- **企业需求匹配**: 拆解型适合明确的分步任务，整合型适合复杂系统设计

### 2. **创作驱动 (creation_drive)**
- **倾向**: logical (逻辑型) ↔ visual (视觉型)
- **0-40分**: 逻辑型 - 灵感来源于规则、结构、因果等理性元素，适合工具开发
- **60-100分**: 视觉型 - 灵感来源于视觉、色彩、空间等感性元素，适合内容创作
- **企业需求匹配**: 视觉型适合设计/内容类任务，逻辑型适合数据/开发类任务

### 3. **工具学习 (tool_learning)**
- **倾向**: manual (手册型) ↔ exploratory (探索型)
- **0-40分**: 手册型 - 先看文档教程，理解原理再动手，基础扎实
- **60-100分**: 探索型 - 拿到新工具直接上手试，边用边学，学习效率高
- **企业需求匹配**: 探索型适合需要快速学习新工具的任务，手册型适合需要深度理解的任务

### 4. **任务执行 (task_execution)**
- **倾向**: iterative (迭代型) ↔ planning (规划型)
- **0-40分**: 迭代型 - 先出粗糙版本再打磨，适合敏捷式项目
- **60-100分**: 规划型 - 动手前先列完整计划，按步骤推进，适合瀑布式项目
- **企业需求匹配**: 规划型适合需要完整方案的任务，迭代型适合快速迭代的任务

### 5. **协作倾向 (collaboration)**
- **倾向**: independent (独立型) ↔ collaborative (协作型)
- **0-40分**: 独立型 - 喜欢自己从头到尾负责完整模块，适合独立接单
- **60-100分**: 协作型 - 喜欢和他人分工配合，各展所长，适合团队项目
- **企业需求匹配**: 独立型适合个人任务，协作型适合团队项目

### 6. **风险态度 (risk_attitude)**
- **倾向**: conservative (稳健型) ↔ adventurous (冒险型)
- **0-40分**: 稳健型 - 倾向选择有把握的任务，确保交付质量，适合常规项目
- **60-100分**: 冒险型 - 愿意挑战没做过的事，边做边学，适合探索性项目
- **企业需求匹配**: 稳健型适合成熟流程任务，冒险型适合创新探索任务

## 动态更新机制

这6个维度的分数会根据每次任务执行情况动态调整：

### 从任务执行中更新维度
1. **任务复杂度 vs 实际拆解情况** → 更新 info_processing
2. **交付物类型 (视觉/逻辑)** → 更新 creation_drive
3. **新工具学习速度** → 更新 tool_learning
4. **执行方式 (有计划/快速迭代)** → 更新 task_execution
5. **沟通频率和协作表现** → 更新 collaboration
6. **是否接受挑战性任务** → 更新 risk_attitude

### 更新触发点
- 任务完成后的企业评价
- AI导师观察到的行为模式
- 学生主动反馈的感受
