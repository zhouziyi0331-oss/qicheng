# 任务评价系统实现文档

> 完成时间：2024年
> 功能状态：✅ 已完成

---

## 📋 功能概述

实现了学生和企业之间的双向评价系统，支持多维度评分、标签选择、文字评价、匿名评价等功能。

---

## 🗄️ 数据库设计

### 新增表结构

#### 1. task_ratings（任务评价表）
```sql
- id: 评价ID
- task_id: 关联任务ID
- rater_id: 评价者ID
- rater_type: 评价者类型（student/company）
- ratee_id: 被评价者ID
- ratee_type: 被评价者类型（student/company）

-- 总体评分
- overall_rating: 总体评分（1-5星）

-- 学生评价企业的维度
- requirement_clarity: 需求清晰度（1-5星）
- communication_quality: 沟通质量（1-5星）
- payment_timeliness: 付款及时性（1-5星）

-- 企业评价学生的维度
- work_quality: 作品质量（1-5星）
- delivery_timeliness: 交付及时性（1-5星）
- professional_attitude: 专业态度（1-5星）

-- 评价内容
- comment: 文字评价
- tags: 标签（JSON数组）
- is_anonymous: 是否匿名
- is_public: 是否公开显示

-- 企业回复
- company_reply: 企业回复内容
- company_reply_at: 回复时间

- created_at: 创建时间
- updated_at: 更新时间
```

#### 2. user_rating_stats（用户评分统计表）
```sql
- user_id: 用户ID
- user_type: 用户类型（student/company）

-- 总体统计
- total_ratings: 总评价数
- average_rating: 平均评分

-- 学生统计
- avg_work_quality: 平均作品质量
- avg_delivery_timeliness: 平均交付及时性
- avg_professional_attitude: 平均专业态度

-- 企业统计
- avg_requirement_clarity: 平均需求清晰度
- avg_communication_quality: 平均沟通质量
- avg_payment_timeliness: 平均付款及时性

-- 星级分布
- five_star_count: 5星数量
- four_star_count: 4星数量
- three_star_count: 3星数量
- two_star_count: 2星数量
- one_star_count: 1星数量

- updated_at: 更新时间
```

#### 3. rating_tag_presets（评价标签预设表）
```sql
- id: 标签ID
- tag_type: 标签类型（student_positive/student_negative/company_positive/company_negative）
- tag_name: 标签名称
- display_order: 显示顺序
- is_active: 是否启用
- created_at: 创建时间
```

#### 4. rating_reminders（评价提醒表）
```sql
- id: 提醒ID
- task_id: 任务ID
- user_id: 用户ID
- user_type: 用户类型
- reminder_count: 提醒次数
- last_reminded_at: 最后提醒时间
- is_completed: 是否已完成
- created_at: 创建时间
```

### 预设标签数据

**学生正面标签：**
- 作品优秀、交付及时、沟通顺畅、态度认真、超出预期、响应迅速、专业能力强、理解能力好

**学生负面标签：**
- 交付延迟、质量不达标、沟通不畅、态度消极、理解偏差、响应缓慢

**企业正面标签：**
- 需求清晰、付款及时、沟通友好、反馈及时、尊重学生、要求合理、验收公正

**企业负面标签：**
- 需求模糊、付款延迟、频繁改需求、沟通困难、要求过高、验收苛刻

### 索引优化
- task_ratings: task_id, rater_id, ratee_id, overall_rating, created_at, is_public
- rating_reminders: task_id, user_id, is_completed

### 触发器
1. **update_rating_updated_at**: 自动更新updated_at字段
2. **update_user_rating_stats**: 评价插入/更新/删除时自动更新用户评分统计

## 🔌 后端API接口

### 基础路径
`/api/v1/rating`

### 接口列表

#### 1. 提交评价
```
POST /submit
Body: {
  taskId: number,
  overallRating: number (1-5),
  // 学生评价企业
  requirementClarity?: number,
  communicationQuality?: number,
  paymentTimeliness?: number,
  // 企业评价学生
  workQuality?: number,
  deliveryTimeliness?: number,
  professionalAttitude?: number,
  // 通用
  comment: string,
  tags: string[],
  isAnonymous: boolean
}
```
- 验证任务状态（必须已完成）
- 验证是否已评价
- 验证评分范围（1-5）
- 自动更新任务的评价状态
- 触发器自动更新用户评分统计

#### 2. 获取任务的评价
```
GET /task/:taskId
```
- 返回任务的所有评价
- 匿名评价隐藏评价者信息
- 只返回公开评价或自己的评价

#### 3. 获取用户的评分统计
```
GET /stats/:userId
```
- 返回用户的总体评分统计
- 包含平均分、各维度评分、星级分布

#### 4. 获取用户收到的评价列表
```
GET /received/:userId?page=1&limit=20
```
- 分页返回用户收到的评价
- 包含评价者信息、任务信息
- 匿名评价隐藏评价者信息

#### 5. 获取用户发出的评价列表
```
GET /given?page=1&limit=20
```
- 分页返回当前用户发出的评价
- 包含被评价者信息、任务信息

#### 6. 企业回复评价
```
POST /:ratingId/reply
Body: {
  reply: string
}
```
- 只有企业可以回复
- 只能回复评价自己的评价

#### 7. 获取评价标签预设
```
GET /tags/presets?tagType=student_positive
```
- 返回指定类型的标签预设
- 用于前端展示标签选项

#### 8. 检查任务是否可以评价
```
GET /check/:taskId
```
- 验证任务状态
- 验证是否已评价
- 返回是否可以评价及原因

#### 9. 获取待评价任务列表
```
GET /pending
```
- 返回当前用户的待评价任务
- 包含对方用户信息

## 📊 数据流程

### 完整评价流程

```
1. 任务完成后
   ↓
2. 学生/企业进入"待评价任务"列表
   ↓
3. 点击"立即评价"按钮
   ↓
4. 调用 GET /rating/check/:taskId 验证是否可以评价
   ↓
5. 进入评价页面，加载标签预设
   ↓
6. 用户填写评分、标签、文字评价
   ↓
7. 点击"提交评价"
   ↓
8. 调用 POST /rating/submit 提交评价
   ↓
9. 后端验证并插入评价记录
   ↓
10. 触发器自动更新用户评分统计
    ↓
11. 更新任务的评价状态（student_rated/company_rated）
    ↓
12. 返回成功，前端显示提示并返回上一页
```

## 🎯 技术亮点

1. **数据库触发器自动化**：使用PostgreSQL触发器自动维护用户评分统计，减少应用层计算
2. **多维度评分**：学生和企业分别有3个专属评分维度，更全面地评价合作质量
3. **标签预设系统**：32个预设标签，方便用户快速选择，提升评价效率
4. **匿名评价保护**：支持匿名评价，保护用户隐私，鼓励真实反馈
5. **评分统计实时更新**：触发器自动计算平均分、星级分布等统计数据
6. **UI主题一致性**：学生端粉色、企业端深色，与整体设计风格保持一致
7. **权限验证完善**：每个接口都验证用户权限和任务状态，确保数据安全

---

## 📈 性能优化

1. **数据库索引**：为常用查询字段添加索引，提升查询速度
2. **触发器优化**：使用数据库触发器自动维护统计数据，减少应用层计算
3. **分页加载**：评价列表支持分页加载，避免一次性加载过多数据
4. **唯一约束**：task_id + rater_id 唯一约束，防止重复评价

---

## 🔒 安全措施

1. **JWT认证**：所有接口需要JWT token认证
2. **权限验证**：验证用户是否为任务参与者
3. **评分范围验证**：验证评分在1-5之间
4. **SQL注入防护**：使用参数化查询
5. **XSS防护**：前端显示时转义HTML特殊字符
6. **重复评价防护**：数据库唯一约束 + 后端验证
