## 🗄️ 数据库设计

### 新增表结构

#### 1. chat_sessions（聊天会话表）
```sql
- id: 会话ID
- task_id: 关联任务ID
- student_id: 学生用户ID
- company_id: 企业用户ID
- status: 会话状态（active/archived/blocked）
- last_message_at: 最后消息时间
- student_unread_count: 学生未读数
- company_unread_count: 企业未读数
- created_at: 创建时间
- updated_at: 更新时间
```

#### 2. chat_messages（聊天消息表）
```sql
- id: 消息ID
- session_id: 会话ID
- sender_id: 发送者ID
- sender_type: 发送者类型（student/company/system）
- message_type: 消息类型（text/image/file/system）
- content: 消息内容
- file_url: 文件URL（可选）
- file_name: 文件名（可选）
- file_size: 文件大小（可选）
- is_read: 是否已读
- read_at: 阅读时间
- created_at: 创建时间
- updated_at: 更新时间
```

#### 3. message_read_status（消息已读记录表）
```sql
- id: 记录ID
- message_id: 消息ID
- user_id: 用户ID
- read_at: 阅读时间
```

### 索引优化
- 会话表：task_id, student_id, company_id, status, last_message_at
- 消息表：session_id, sender_id, created_at, is_read
- 已读记录表：message_id, user_id

### 触发器
1. **update_chat_session_last_message**: 新消息插入时自动更新会话的最后消息时间和未读计数
2. **update_chat_session_unread_count**: 消息标记已读时自动减少未读计数
3. **update_updated_at_column**: 自动更新updated_at字段

## 🔌 后端API接口

### 基础路径
`/api/v1/chat`

### 接口列表

#### 1. 获取或创建聊天会话
```
POST /sessions
Body: {
  taskId: number,
  studentId: number,
  companyId: number
}
```
- 验证任务存在且学生已接单
- 如果会话不存在则创建新会话
- 自动发送系统欢迎消息

#### 2. 获取用户的所有聊天会话列表
```
GET /sessions
```
- 返回当前用户的所有活跃会话
- 包含对方用户信息、任务信息、未读数、最后消息
- 按最后消息时间倒序排列

#### 3. 获取会话的聊天记录
```
GET /sessions/:sessionId/messages?page=1&limit=50
```
- 分页获取聊天记录
- 包含发送者信息（昵称、头像）
- 按时间正序返回

#### 4. 发送消息
```
POST /sessions/:sessionId/messages
Body: {
  content: string,
  messageType: 'text' | 'image' | 'file',
  fileUrl?: string,
  fileName?: string,
  fileSize?: number
}
```
- 验证会话权限和状态
- 自动更新会话的最后消息时间
- 自动增加对方的未读计数

#### 5. 标记消息为已读
```
POST /sessions/:sessionId/read
```
- 批量标记会话中所有未读消息为已读
- 自动减少未读计数
- 记录已读状态

#### 6. 获取未读消息总数
```
GET /unread-count
```
- 返回用户所有会话的未读消息总数

#### 7. 归档会话
```
POST /sessions/:sessionId/archive
```
- 将会话状态设置为archived
- 不再显示在活跃会话列表中

## 🔐 权限控制

### 会话创建权限
- 只有任务的学生和企业才能创建会话
- 学生必须已接单（status = accepted/in_progress/submitted）

### 消息查看权限
- 只有会话的参与者（学生或企业）才能查看消息

### 消息发送权限
- 只有会话的参与者才能发送消息
- 会话状态必须为active

## 📊 数据流程

### 完整聊天流程

```
1. 学生接单后
   ↓
2. 企业或学生点击"联系对方"
   ↓
3. 调用 POST /sessions 创建或获取会话
   ↓
4. 跳转到聊天详情页面
   ↓
5. 加载聊天记录 GET /sessions/:id/messages
   ↓
6. 自动标记为已读 POST /sessions/:id/read
   ↓
7. 用户输入消息并发送 POST /sessions/:id/messages
   ↓
8. 消息插入数据库
   ↓
9. 触发器自动更新会话的last_message_at和未读计数
   ↓
10. 对方打开聊天列表时看到新消息和未读角标
    ↓
11. 对方进入聊天详情，自动标记已读
```
